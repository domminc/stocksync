# StockSync — 매장·온라인 통합 재고관리

바코드 스캔으로 매장 재고를 관리하고, 온라인(플레이오토 등) 주문까지 **하나의 재고 풀**로 관리하는 웹 시스템입니다.
기획안(Figma)의 Phase 1~2 범위를 구현한 첫 버전입니다.

## 핵심 규칙

| 규칙 | 내용 |
| --- | --- |
| 재고 풀 | 매장 1개 + 온라인을 **하나의 재고**로 관리. `판매 가능(qty)` + `보류(hold)` |
| 차감 시점 | **출고확정** 때만 차감. 온라인 주문을 가져와도 재고는 그대로, 대신 “미출고 주문”과 “오버셀 위험”으로 경고 |
| 원장 | 모든 증감은 `stock_ledger`에 기록. DB 트리거로 **수정·삭제 불가** |
| 음수 재고 | 불가. 출고·확정 시 부족하면 **전체가 취소**되고 아무것도 바뀌지 않음 |
| 개인정보 | 주문 파일의 구매자·수령인·연락처·주소는 **읽지도 저장하지도 않음** (읽는 열은 `src/lib/orders.js` 상단 목록뿐) |
| 권한 | 5개 역할. 화면과 서버 양쪽에서 검사 (`src/lib/permissions.js`) |

### 역할별 권한

| 역할 | 할 수 있는 일 |
| --- | --- |
| 본사 관리자 `admin` | 모든 기능 + 사용자 관리 |
| 매장 관리자 `manager` | 상품 등록·가져오기, 입고·출고, 재고 조정, 온라인 주문 처리·반품 |
| 매장 직원 `staff` | 입고·출고 스캔, 조회 |
| 온라인 운영자 `online` | 주문 가져오기·출고확정·취소·반품·상품 연결, 조회 |
| 조회 전용 `viewer` | 조회만 |

## 실행

Node.js 22.13 이상 (내장 SQLite 사용, 외부 DB 불필요).

```sh
npm ci
npm run create-admin -- admin "관리자"      # 비밀번호 10자 이상을 입력
npm start                                    # http://127.0.0.1:3000
```

화면만 먼저 보고 싶다면 샘플 데이터를 넣을 수 있습니다 (운영 DB에는 사용 금지).

```sh
DB_PATH=data/demo.db npm run seed -- 300     # 로그인: admin/manager/staff/online/viewer, 비밀번호 demo-password-1234
DB_PATH=data/demo.db npm start
```

환경 변수는 `.env.example` 참고. 운영 배포·백업은 [docs/OPERATIONS.md](docs/OPERATIONS.md).

## 사용 순서 (처음 도입할 때)

1. **상품 목록 만들기** — 재고를 관리할 상품·옵션 목록(상품명, 옵션, 가능하면 상품코드)을 CSV로 올립니다. **바코드 열이 비어 있으면 이 시스템이 EAN-13 바코드를 자동 발급**합니다. `현재고` 열이 있으면 초기 재고로 원장에 기록됩니다. 10만 건 기준 약 8초.
   - 상품 목록 파일이 없다면: 플레이오토/스마트스토어/쿠팡의 상품(옵션) 목록 엑셀을 CSV로 저장해 올리거나, 판매 이력으로 초안을 만듭니다 → `node scripts/orders-to-products.js 주문파일.csv 초안.csv`
2. **라벨 인쇄** — 발급한 바코드를 라벨로 인쇄해 상품에 붙입니다 (아래 “바코드와 라벨”).
3. **입고/출고 스캔** — 스캐너로 바코드를 읽고(Enter) 목록을 확인한 뒤 “확정”. 확정 전에는 재고가 바뀌지 않습니다.
4. **주문 가져오기** — 플레이오토 등의 주문 CSV 업로드. 주문 파일에 상품코드가 없어도 **상품명(“상품명 / 옵션: 값”)으로 자동 매칭**합니다. 못 찾은 것은 **매칭 대기**에서 후보를 보고 한 번 연결하면 이후 자동입니다.
5. **온라인 출고 스캔** — 포장하면서 상품을 스캔하면 가장 오래된 미출고 주문이 출고확정되고 재고가 차감됩니다.
6. 취소·반품은 주문 목록에서 처리. 반품은 양품(판매 가능으로) / 불량(보류로) 선택.

### 바코드와 라벨

- **자체 발급 바코드:** `20` + 일련번호 10자리 + 체크디지트의 EAN-13. 20~29로 시작하는 번호는 GS1이 매장 내부용으로 비워 둔 범위라 회사 안에서 자유롭게 쓸 수 있습니다. 같은 번호가 두 번 나가지 않으며, 이미 쓰는 번호는 건너뜁니다.
- **주의:** 자체 발급 번호는 매장·창고 내부용입니다. 쇼핑몰 상품 등록이나 오프라인 유통에 GS1 정식 바코드가 필요하다면 그 번호는 “바코드” 열에 넣어 가져오세요 (기존 바코드로 취급, 라벨도 그대로 출력).
- **라벨 인쇄:** `라벨 인쇄` 메뉴 또는 상품 목록의 “라벨 인쇄 (검색 결과)”. 크기는 롤 50×30mm / 40×25mm / A4 여러 장. 장수는 “상품마다 같은 장수” 또는 “현재 재고 수량만큼”. 한 번에 최대 3,000장.
  인쇄 창에서 **용지 크기를 라벨 크기에 맞추고 여백을 ‘없음’**으로 설정하세요 (처음 한 번). 출력 후 “출력 완료”로 표시하면 `라벨 미출력` 목록에서 빠집니다.
- 숫자 13자리가 아닌 외부 바코드(영문 포함 등)는 막대 대신 번호만 인쇄됩니다 (Code128 미지원).

### 상품명으로 주문 매칭

주문 파일에 상품코드가 없으면 `상품명 / 옵션: 값 / 옵션: 값` 문구를 상품 목록의 상품명·옵션과 비교합니다.
앞쪽 `[오늘출발]` 같은 말머리, 공백·기호, `사이즈:` 같은 옵션 이름표, 옵션 순서의 차이는 무시합니다. 같은 키의 상품이 둘 이상이면 임의로 고르지 않고 매칭 대기로 보냅니다.
`┗(추가상품)` 줄(자수·각인 신청 등)은 자동 제외하고, 그 밖의 재고와 무관한 항목은 매칭 대기에서 “재고와 무관”으로 한 번 표시하면 이후 자동 제외됩니다.
실제 판매 이력 6.9만 줄로 시험했을 때 정규화·매칭·가져오기는 2.7초에 처리됩니다.

### CSV 형식

- 문자 인코딩은 UTF-8 또는 엑셀 CSV(CP949) 모두 자동 인식. 구분자는 쉼표/탭/세미콜론 자동.
- 열 이름은 공백·대소문자를 무시하고 여러 이름을 인식합니다 (예: 주문번호/쇼핑몰주문번호, 바코드/판매자관리코드/상품코드).
- 엑셀에서 바코드 열이 `8.8E+12`처럼 변형되면 해당 행을 거부하고 이유를 알려 줍니다. 바코드 열은 **텍스트 서식**으로 저장하세요.
- 같은 주문 파일을 다시 올려도 중복되지 않습니다. 배송중·구매확정 등 이미 나간 주문은 “외부 출고됨”으로 기록되어 재고에 반영되지 않습니다 (도입 시점 이전 주문이 재고를 깎는 사고 방지).
- 양식은 각 가져오기 화면의 “양식 내려받기”.

## 구조

```text
src/app.js            Express 설정, 보안 헤더, 세션/CSRF/권한 가드
src/routes/           화면별 라우트 (auth, dashboard, products, stock, orders, labels, users)
scripts/responsive-check.mjs  여러 화면 폭 자동 점검 (playwright-core 필요)
src/lib/inventory.js  재고 증감·원장·출고확정·반품 (핵심 규칙은 여기)
src/lib/products.js   상품 검증·검색·CSV 가져오기·대시보드 집계
src/lib/orders.js     주문 CSV 가져오기·매칭(코드/상품명)·상태 해석
src/lib/namekey.js    상품명+옵션 정규화 (주문 ↔ 상품 매칭 키)
src/lib/barcodes.js   자체 EAN-13 발급, 라벨용 막대(SVG) 생성
src/lib/csv.js        CSV 파서, 인코딩 감지, 열 이름 인식
src/lib/auth.js       비밀번호(scrypt), 세션, 로그인 잠금
views/ public/        EJS 템플릿, CSS/JS (인라인 스타일·스크립트 없음: CSP 준수)
migrations/           SQL 마이그레이션 (순서대로 자동 적용)
tests/                node:test 기반 단위·통합 테스트
```

## 반응형

| 화면 폭 | 동작 |
| --- | --- |
| 901px 이상 | 왼쪽 고정 메뉴 + 본문 (1500px 이상은 본문을 가운데로) |
| 900px 이하 (태블릿·폰) | 메뉴는 `☰ 메뉴` 버튼으로 여는 서랍 (Esc 로 닫기), 상단 바 고정, 사용자 정보·로그아웃은 서랍 아래 |
| 640px 이하 (폰) | 목록 표(상품·주문·원장·스캔 목록 등)는 카드로, 폼은 세로로, 버튼·입력은 44px 높이(16px 글자 — iOS 확대 방지), 스캔 확정 바는 화면 아래 고정 |

**목록 개수:** 상품·주문·재고 원장 목록은 폰(640px 이하)에서 **10개씩**, 그 밖(PC·태블릿)에서 **20개씩** 보여 주고 쪽으로 나뉩니다. 쪽이 8개 이상이면 “쪽 이동” 입력이 나옵니다.
서버는 화면 폭을 모르므로 브라우저가 알려 주는 쿠키(`dv`)를 쓰고, 처음 접속이면 접속 기기(User-Agent)로 추정한 뒤 실제 폭과 다르면 한 번만 다시 불러옵니다. 개수를 바꾸려면 `src/lib/pagesize.js`.

메뉴는 CSS 만으로 동작하고(자바스크립트 없이), 인쇄(라벨)에는 모바일 규칙이 적용되지 않습니다.
화면을 고칠 때는 아래 점검을 돌려 보세요 — 5개 화면 폭 × 18개 화면에서 가로 넘침, 메뉴 열기/닫기, 카드 변환, 터치 크기, 스캔 화면 동작을 확인합니다.

```sh
npm run check:responsive                # 문제가 있으면 목록을 출력하고 종료 코드 1
npm run check:responsive -- --shots     # responsive-shots/ 에 스크린샷 저장
```

## 알려진 한계 (다음 단계 후보)

- 엑셀 `.xlsx` 직접 업로드는 미지원 — CSV로 저장해 올립니다.
- 플레이오토/쇼핑몰 **API 자동 수집**은 미구현 (CSV 업로드로 시작).
- 스마트폰 카메라 바코드 스캔 미구현 (스캐너 우선).
- 실사(전체 재고조사) 세션 기능은 미구현 — 현재는 상품별 “재고 조정”.
- 안전재고 이메일/메신저 알림 없음 — 대시보드·목록의 부족/품절 표시만.
- 발주(구매) 관리 없음. 라벨은 EAN-13 숫자 바코드만 막대로 출력.
